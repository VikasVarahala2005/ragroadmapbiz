Module 1: RAG Fundamentals and Architecture

1.1 Introduction to RAG - Complete Deep Dive

PART 1: What is RAG?

1. What is This?
RAG = Retrieval-Augmented Generation
In the simplest possible words:
RAG is a technique where an AI, before answering your question, first goes and searches for relevant information from a knowledge base — and then uses that retrieved information to generate a better, more accurate answer.

Think of it as giving the AI the ability to "look things up" before speaking[cite: 13].

2. Why Do We Need It?

The Core Problem: LLMs Are Frozen in Time[cite: 13]

When a Large Language Model (LLM) like GPT-4 is trained, it learns from a massive dataset[cite: 13]. But after training ends — it knows nothing new[cite: 13].

Imagine a brilliant professor who[cite: 13]:

  • Read every book ever written... but only until December 2023[cite: 13]
  • Has no internet access[cite: 13]
  • Cannot access your company's private documents[cite: 13]
  • Sometimes confidently makes things up when unsure (hallucination)[cite: 13]

That professor is your LLM[cite: 13]. RAG solves 4 critical problems that LLMs face[cite: 13]:

  1. Knowledge Cutoff: LLMs cannot answer questions about events or data after their training end date[cite: 13].
  2. Private Data Access: LLMs do not have access to proprietary enterprise files, user-specific data, or internal databases[cite: 13].
  3. Hallucinations: When uncertain, standard generative models tend to fabricate factual-sounding but incorrect information[cite: 13].
  4. Lack of Provenance: Standard LLM responses cannot easily cite exact page numbers or specific document source files[cite: 13, 14, 15].

Module 2: Document Processing and Chunking

The Foundation That Makes or Breaks Your RAG System[cite: 14]

GARBAGE IN → GARBAGE RETRIEVED → GARBAGE ANSWER
The retriever can only find what was properly stored[cite: 14]. The LLM can only answer from what the retriever finds[cite: 14].
Document Processing = The Foundation of Everything in RAG[cite: 14]
A perfect LLM + perfect vector store + bad chunking = broken RAG system[cite: 14].

PART 1: Document Loaders in LangChain

1. What is a Document Loader?

Simple Definition: A Document Loader is a tool that reads raw files (PDFs, web pages, CSVs, etc.) and converts them into a standardized format that the RAG pipeline can work with[cite: 14].

Standard Output: Every loader outputs a LangChain Document object containing exactly two fields[cite: 14]:

Document(
    page_content = "The actual text content here...",
    metadata = {
        "source": "hr_policy.pdf",
        "page": 3,
        "author": "HR Department",
        # any other useful information
    }
)

2. PDF Loaders — Deep Dive

PDF was designed for printing, not text extraction[cite: 14]. Challenges include multi-column layouts, tables, headers/footers, scanned images, mathematical formulas, embedded graphics, and footnotes[cite: 14].

Loader Speed Accuracy Tables Handling Best Use Cases
PyPDFLoader Fastest[cite: 14] Basic[cite: 14] Poor[cite: 14] Simple text-based PDFs, quick prototyping[cite: 14].
PDFMinerLoader Medium[cite: 14] Good[cite: 14] Partial[cite: 14] Complex text layouts, complex fonts, reading order preservation[cite: 14].
PDFPlumberLoader Medium[cite: 14] Best[cite: 14] Excellent[cite: 14] Financial reports, research papers, explicit table structures[cite: 14].
UnstructuredPDFLoader Slowest[cite: 14] Best[cite: 14] Excellent[cite: 14] Scanned PDFs requiring OCR, complex mixed-layout media[cite: 14].
PyPDFLoader Example:
from langchain_community.document_loaders import PyPDFLoader

loader = PyPDFLoader("documents/hr_policy.pdf")
pages = loader.load()

print(f"Total pages: {len(pages)}")
print(f"First page content: {pages[0].page_content[:200]}")
print(f"First page metadata: {pages[0].metadata}")

3. Web Loaders

WebBaseLoader: Extract single or multiple specific URLs[cite: 14].

from langchain_community.document_loaders import WebBaseLoader
import bs4

loader = WebBaseLoader(
    web_paths=["https://docs.python.org/3/tutorial/"],
    bs_kwargs=dict(
        parse_only=bs4.SoupStrainer(
            class_=("post-content", "post-title", "post-header")
        )
    ),
)
docs = loader.load()

RecursiveUrlLoader: Crawl entire websites up to a set depth[cite: 14].

from langchain_community.document_loaders.recursive_url_loader import RecursiveUrlLoader
from bs4 import BeautifulSoup

def bs4_extractor(html: str) -> str:
    soup = BeautifulSoup(html, "lxml")
    for script in soup(["script", "style"]):
        script.decompose()
    return soup.get_text(separator="\n", strip=True)

loader = RecursiveUrlLoader(
    url="https://docs.langchain.com/",
    max_depth=3,
    extractor=bs4_extractor,
    prevent_outside=True
)
docs = loader.load()

4. Structured Data Loaders (CSV, JSON, Directory)

from langchain_community.document_loaders import CSVLoader, JSONLoader, TextLoader, DirectoryLoader

# CSV Loader
csv_loader = CSVLoader(

PART 2: Text Splitting Strategies

1. Why Do We Need to Split?

Technical constraints demand document chunking[cite: 14]:

  • Context Window Limits: Models have token bounds (e.g., GPT-4 at 128k, Claude at 200k)[cite: 14]. Large prompts increase latency and cost[cite: 14].
  • Retrieval Precision: Focused chunks reduce retrieval noise and prevent LLM confusion[cite: 14].
  • Embedding Quality: Dense embedding models capture precise semantics for focused chunks (128–512 tokens) better than entire books[cite: 14].

2. RecursiveCharacterTextSplitter

Splits hierarchically using natural separators[cite: 14]: ["\n\n", "\n", " ", ""][cite: 14].

from langchain_text_splitters import RecursiveCharacterTextSplitter
import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

splitter = RecursiveCharacterTextSplitter(
    chunk_size=256,
    chunk_overlap=25,
    length_function=lambda x: len(enc.encode(x)),
    separators=["\n\n", "\n", " ", ""]
)

3. Semantic Chunking

Detects topic transitions based on vector distance between adjacent sentences[cite: 14].

from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

splitter = SemanticChunker(
    OpenAIEmbeddings(),
    breakpoint_threshold_type="percentile", # "percentile", "standard_deviation", or "gradient"
    breakpoint_threshold_amount=70
)
docs = splitter.create_documents([long_text])

4. Markdown and Code-Specific Splitters

from langchain_text_splitters import MarkdownTextSplitter, RecursiveCharacterTextSplitter, Language

# Markdown
md_splitter = MarkdownTextSplitter(chunk_size=200, chunk_overlap=20)

# Code (Python, JS, C, Go, etc.)
py_splitter = RecursiveCharacterTextSplitter.from_language(
    language=Language.PYTHON,
    chunk_size=500,
    chunk_overlap=50
)

PART 3: Chunking Best Practices

Use Case Recommended Chunk Size Reasoning
Factoid Queries 128 – 256 tokens[cite: 14] Single-fact precision; prevents diluted embeddings[cite: 14].
General RAG (Standard) 256 – 512 tokens[cite: 14] Sufficient context while preserving embedding focus[cite: 14].
Complex Analysis 512 – 1024 tokens[cite: 14] Captures multi-step rationale and linked concepts[cite: 14].
Document Summaries Parent-Child / Hierarchical[cite: 14] Links small retrieval chunks to large contextual parents[cite: 14].
Overlap Rule of Thumb: Maintain a 10% – 20% chunk overlap relative to overall chunk size to preserve semantic continuity across chunk boundaries[cite: 14].

PART 5: Failure Modes, Interview Prep, & Exercises

7 Common Failure Modes:
  1. Wrong PDF Loader Choice (e.g., using standard PyPDF on scanned images)[cite: 14].
  2. Tiny Chunk Size (< 50 tokens) creating fragmented, meaningless text[cite: 14].
  3. Zero Overlap breaking sentences and context across boundaries[cite: 14].
  4. Encoding Errors (missing explicit utf-8 encoding)[cite: 14].
  5. Inconsistent metadata schemas crashing filter operations[cite: 14].
  6. Ingesting empty or whitespace-only documents[cite: 14].
  7. Arbitrary splitting across data tables without structure preservation[cite: 14].

Module 3: Embeddings and Vector Representations

The Mathematical Heart of RAG[cite: 15]

PART 1: How Embeddings Work

An embedding converts text into a continuous array of floating-point numbers (vector) where spatial proximity correlates directly with semantic similarity[cite: 15].

Distance Metrics Comparison

Metric Mathematical Formula Range Best Used For
Cosine Similarity (A · B) / (||A|| × ||B||)[cite: 15] [-1.0, +1.0][cite: 15] Text & NLP; invariant to length variation[cite: 15].
Euclidean Distance (L2) sqrt( Σ (a_i - b_i)² )[cite: 15] [0, +∞)[cite: 15] Fixed-length normalized vectors, image features[cite: 15].
Dot Product (Inner Product) Σ (a_i × b_i)[cite: 15] (-∞, +∞)[cite: 15] Normalized vectors (faster, identical ranking to Cosine)[cite: 15].

PART 2: Embedding Models Overview

Standard proprietary models include OpenAI's text-embedding-3-small (1536 dims default, scaleable down via Matryoshka learning) and text-embedding-3-large (3072 dims)[cite: 15].

Local and open-source models (via Ollama or HuggingFace) include nomic-embed-text, bge-large-en-v1.5, and all-MiniLM-L6-v2[cite: 15].

from langchain_ollama import OllamaEmbeddings
from langchain_openai import OpenAIEmbeddings

# Local Ollama Embeddings
local_embed = OllamaEmbeddings(model="nomic-embed-text")

# OpenAI Embeddings
openai_embed = OpenAIEmbeddings(
    model="text-embedding-3-small",
    dimensions=1536
)

PART 3: Choosing the Right Embedding Model

MTEB (Massive Text Embedding Benchmark) evaluates models across 56 tasks[cite: 15]. For RAG architectures, focus specifically on the Retrieval (NDCG@10) score and verify model maximum context sequence length limits (e.g., 512 vs 8192 tokens)[cite: 15].

PART 4: LangChain Embeddings Implementation

Crucial Distinction: Use embed_query() for user search inputs and embed_documents() for knowledge base ingestion to handle asymmetric embedding models (e.g., E5 or BGE)[cite: 15].

# Correct usage pattern
query_vector = embeddings.embed_query("What is the vacation policy?")
doc_vectors = embeddings.embed_documents(["Policy text block 1...", "Policy text block 2..."])

PART 5: Failure Modes & Interview Preparation

Critical Embedding Pitfalls:
  • Model Mismatch: Indexing documents with one embedding model and querying with another yields random vector alignment[cite: 15].
  • Truncation Loss: Exceeding max model sequence bounds silently drops trailing chunk tokens[cite: 15].
  • Method Misuse: Invoking embed_documents on user queries in asymmetric retrieval setups degrades precision[cite: 15].
  • Domain Mismatch: Using general web embeddings on complex clinical, legal, or financial nomenclature[cite: 15].
